セカンドブレインは、放っておくと物置になる。

僕のObsidian Vaultには `00_InBox` というフォルダがある。思いついたこと、読んだ記事のメモ、書きかけの断片——とりあえず全部ここに放り込む。これ自体はいい運用だ。問題は、**放り込んだあと誰も片付けないこと**だった。

タグもついていない。他のノートとも繋がっていない。InBoxの中で、ノートは孤島のまま積み上がっていく。検索しても引っかからず、グラフビューにも現れない。書いた時点で、ほぼ存在しないノートになる。

「あとで整理する」は永遠に来ない。だったら、整理する作業そのものを自分の手から外せばいい。**毎晩、寝ている間にAIにタグと関連リンクをつけてもらう。** そう決めて作ったのが、今回の仕組みだ。

## 何をしてくれるのか

やることは地味だが、効く。

- 対象フォルダの各ノートをAIが読む
- 内容にふさわしいタグを3〜8個、YAMLフロントマターに追加する
- Vault内の既存ノートから関連しそうなものを選び、末尾に `## 関連ノート` として wikilink を張る
- 既にタグがついているノートはマージするだけで、上書きしない

朝起きると、昨日まで裸だったノートにタグがつき、関連する過去のノートへのリンクが生えている。グラフビューを開くと、孤島だったノートが本土と橋で繋がっている。**自分では何もしていないのに、セカンドブレインが勝手に育っている**感覚がある。これが思いのほか気持ちいい。

## まずはローカルLLMで素朴に作ってみた

最初の一歩は、手元の[Ollama](https://ollama.com/)で動かす素朴なスクリプトだった。コード自体はAI（Qwen3 Coder）に書かせた。やっていることは単純で、InBoxのmdファイルを順に読み、ローカルのllama3にタグを聞いて、フロントマターに書き戻すだけ。

```python
def get_tags_from_ollama(text):
    prompt = f"""
    以下のテキストを読んで、適切なタグを3つ以下で出力してください。
    タグは # から始まる形式で、スペース区切りで出力してください。
    テキスト: {text[:1000]}

    出力例: #日記 #健康 #生活
    """
    payload = {"model": "llama3", "prompt": prompt, "stream": False}
    response = requests.post(OLLAMA_URL, json=payload, timeout=30)
    result = response.json()
    tags_text = result['response'].strip()
    return [t for t in tags_text.split() if t.startswith('#')][:3]
```

完全オフラインで、APIコストもゼロ。動かしてみると、それっぽくタグはつく。「お、いけるじゃん」と思った。

……が、運用に乗せようとした瞬間、雲行きが怪しくなった。

## AIに自己添削させたら、穴だらけだった

せっかくなので、このコードを別のモデル（Gemma 4 27b）に「実運用の視点でレビューして」と投げてみた。返ってきた指摘が、見事に痛いところを突いていた。要約すると三つ。

**安全性。** 自前のパーサで `yaml.dump` を使ってフロントマターを書き戻すと、本文のMarkdown記法（改行やインデント）まで書き換わる恐れがある。**大切なノートの書式が静かに壊れる**——毎晩自動で回すスクリプトでこれは致命的だ。移動先フォルダが無ければ落ちるし、同名ファイルがあれば黙って上書きする危険もある。

**堅牢性。** `content.startswith('---')` という判定は、冒頭に空行が一つあるだけで失敗する。さらにローカルLLMは「はい、タグは #日記 #仕事 です」のように前置きを付けて返してくることが多く、その挨拶文の単語までタグとして誤検出してしまう。`print` しか出していないので、夜中に失敗しても原因を追えない。

**精度。** 「JSONで返せ」と明示しないと出力が安定しない。1ファイルずつの逐次処理なので件数が増えると遅い。

要するに、**「一度手で動かす」には十分だが、「毎晩無人で回す」には全く足りていなかった。** 自分で書いたコードをAIに添削させると、自分の甘さが客観的に可視化されて気まずい。でも、この気まずさこそが一番の収穫だった。

## 最終的に、手元のclaude CLIに丸投げする形に落ち着いた

指摘を踏まえて作り直すうちに、設計方針が二つ固まった。

ひとつは、**出力をJSONに固定して、余計なものを返させないこと。** ローカルLLMが前置きの挨拶を返してくる問題は、「JSONのみ返す。説明文・コードブロック不要」と明示し、出力形式の見本まで書くことでほぼ解決した。返ってきたテキストから `grep -o '{.*}'` でJSON部分だけ抜き出し、Pythonで `json.loads` する。タグの個数も「3〜8個、#なし」とルールで縛る。表記揺れが気になるほどはバラつかず、賢いモデルだと「#健康」「#ヘルス」のような揺れも自然に抑えられた。

もうひとつは、**タグだけでなく「関連ノート」まで張らせること。** タグは分類だが、リンクは文脈だ。セカンドブレインの価値は後者にある。そこでVault内の既存ノート名一覧を一緒に渡し、「この中から関連するものを選べ」と指示した。存在しないノート名を勝手に作られないよう、返ってきた候補は実在チェックで弾く。

精度と表記の安定を考えると、ここはローカルのllama3よりもっと賢いモデルに任せたい。とはいえ、わざわざAPIキーを管理してSDKを書くのも億劫だ。そこで気づいた——**手元にはすでに `claude` のCLIが入っている。** Claude Codeの実行バイナリだ。これに `claude -p` でプロンプトを流し込めば、APIキーの管理もSDKのインストールも要らず、賢いモデルの出力がそのまま返ってくる。シェルスクリプトから `echo "$PROMPT" | claude -p` と書くだけでいい。プロンプトはこんな構造にした。

```bash
PROMPT="あなたはObsidianナレッジベースの整理アシスタントです。
以下のノートを分析し、タグと関連ノートをJSONで返してください。

## ノート名
${NOTE_NAME}

## ノート内容
${CONTENT_TRUNCATED}

## Vault内の既存ノート一覧（wikilink候補）
${ALL_TITLES}

## 回答ルール
- JSONのみ返す。説明文・コードブロック不要
- tagsは3〜8個、#なしで日本語または英語
- related_notesは0〜5個、必ずVault内の既存ノート一覧から選ぶ
- 関連性が薄いノートは含めない

## 出力形式
{\"tags\": [\"タグ1\"], \"related_notes\": [\"ノート名1\"]}"

# 手元のclaude CLIに流し込むだけ
RESULT=$(echo "$PROMPT" | claude -p --output-format text)
```

そして、Gemma の指摘した安全性の穴をひとつずつ塞いだ。

- **既存タグはマージ**。AIの提案で上書きせず、`dict.fromkeys` で重複を除いて足すだけにした。手でつけたタグが消えない。
- **本文を壊さない**。フロントマターの `tags:` 行だけを正規表現で差し替え、本文は一切触らない。
- **dry-run を用意**。`--dry-run` をつければ、何も保存せず「どんなタグ・リンクがつくか」だけを表示する。いきなり全ノートに書き込むのは怖いので、まずこれで挙動を確認してから本番を回す。
- **対象/除外フォルダを明示**。`publish` や添付ファイル、Templaterのテンプレートなど、触ってほしくない場所は最初から除外する。

```bash
# まずは様子見（保存しない・最初の10件だけ）
./tag_and_link.sh --dry-run --limit 10

# 問題なければ本番
./tag_and_link.sh
```

実際に全Vaultへ流したログを眺めると、こんな調子でひたすら処理が流れていく。

```
[UPD] 愛着スタイル.md | tags+2:思考, 読書 | links+4
[UPD] AIから読み解く社会  権力化する最新技術.md | tags+5:AI, キャリア, 思考, 社会, 読書 | links+3
[UPD] タイム・オフ  働き方に"生産性"と"創造性"を取り戻す戦略的休息術.md | tags+5:... | links+5
```

何百件もの過去ノートに、一晩で一気にタグとリンクが張られていく様子は、なかなか壮観だった。

## ローカルLLMと賢いモデル、結局どう使い分けたか

この一件で腑に落ちたことがある。**「全部ローカルで完結させる」のが常に正解とは限らない**、ということだ。

完全オフラインのローカルLLMは魅力的だし、プライバシーの観点でも理想に近い。実際、最初のプロトタイプはOllamaで十分作れた。でも、**Vault全体のタグ体系を一貫させる**とか、**数百のノートタイトルの中から関連先を正確に選ぶ**といった、語彙と精度がものを言うタスクになると、もっと賢いモデルに任せたほうが結果がいい。

そして「賢いモデルを使う＝APIキーを取ってSDKを書く」とは限らない、というのが今回の地味な発見だった。**Claude CodeのCLIがすでにマシンに入っているなら、`claude -p` にパイプで流し込むのが一番ラクだ。** APIキーの管理も、`anthropic` パッケージのインストールも要らない。シェルスクリプト一枚で、賢いモデルの判断をそのまま運用に組み込める。

ローカルで素朴に作る → AIに添削させて穴を知る → 手元にある道具で賢いモデルに繋ぐ。この往復をやったおかげで、「自分が何を自動化したいのか」がかえってクリアになった。

## 次にやりたいこと

仕組みはできたので、あとは**毎晩自動で回す**だけだ。`launchd` か cron で深夜に実行し、新着・更新されたノートだけを対象に差分処理する。ログをデイリーノートに吐き出して、「昨晩、何件にどんなタグがついたか」を朝にざっと確認できるようにしたい。

整理を自分の手から外したことで、InBoxに気軽にメモを放り込めるようになった。**片付けを気にせず散らかせる**——逆説的だけど、これが一番の効果かもしれない。
