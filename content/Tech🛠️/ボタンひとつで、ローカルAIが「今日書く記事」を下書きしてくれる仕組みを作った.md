ブログを書くとき、一番しんどいのはどこか。人によって違うと思う。僕の場合は、**ネタを記事の長さまで膨らませること**だ。「これを書こう」と思いつくところまではいい。一文か二文のメモにはなる。でも、そこから一本の記事になるまで話を広げて、具体例を足して、流れを作る——その膨らませる工程で、毎回ペンが止まる。

僕のObsidianには考えごとを放り込むフォルダがある。「効率的な読書法」「通勤時間の使い方」「ノートの粒度」——書けば記事になりそうなタネが何十個も眠っている。眠ったまま、何ヶ月も。**タネはあるのに、それを膨らませる体力が出てこない**から、メモのまま塩漬けになる。

だったら、その膨らませる作業をAIにやってもらえばいい。**ボタンを押すと、ローカルのAIがVaultを読んで面白そうなタネを1本選び、それを記事の長さまで膨らませて下書きにしてくれる。** そういう仕組みを作った。

## 何ができるのか

使い方は、文字どおりボタンひとつだ。

1. Obsidianのダッシュボードノートで「📝 今日のおすすめ記事を生成」を押す
2. ローカルAIが のメモを読んで、記事になりそうなネタを1つ選ぶ
3. 元メモの内容と、過去に公開した記事の文体を渡して、**フルの下書きを生成**する
4. `Draft` フォルダに `status: draft` 付きで保存される
5. 僕がそれを読んで、良ければ `publish/` のカテゴリへ移動するだけ

朝にボタンを押しておけば、コーヒーを淹れて戻ってくる頃には、下書きが1本できている。一文のメモを記事まで膨らませるのと、「すでに膨らんだ7割の下書きを削って整える」のとでは、心理的な負荷がまるで違う。**いちばん腰の重い"膨らませる"工程を、ボタンひとつ分まで肩代わりできた。**

ポイントは、生成物を直接 `publish` に入れないことだ。あくまで `Draft` に溜める。AIの下書きはそのままでは公開しない。僕が目を通し、手を入れ、納得したものだけが世に出る。AIは「膨らませて下書きにする」担当で、削って整え、世に出す最終責任は人間が持つ。この線引きが、安心して任せるための前提になっている。

## なぜローカルLLMなのか、そしてモデル選び

クラウドのAPIを使えば、もっと賢いモデルが簡単に使える。それでもローカルにこだわったのは、**自分の思考の断片を全部読ませる**仕組みだからだ。まだ誰にも見せていない考えごとのメモを、丸ごとモデルに渡す。それを自分のMacの中だけで完結させたかった。

問題は「ローカルでどこまで賢いモデルが動くか」だ。これは結局、手元のM5 MacBook Air（ユニファイドメモリ24GB）に**載る最大サイズ**で決まる。

最初に有力だと思ったのはQwen3.6の27B（MLX版）。ところが動かすと `model requires 18.4 GiB but only 17.3 GiB are available` で落ちた。盲点だったのは、**24GBあってもmacOSがGPUに割り当てる上限が既定で約75%（≒17GiB）に絞られている**こと。`sudo sysctl iogpu.wired_limit_mb` で上げられるが、毎回それを前提にするのは避けたかった。

そこで「設定をいじらず確実に載るモデル」に方針転換した。gpt-oss:20bは素直に動くが日本語が時々崩れる（英語圏のモデルの弱点だ）。軽いGemmaは流暢だが小さい。……と試すうちに、もっと大事なことに気づいた。**問題はモデルの大きさより、プロンプトの方だった。**

どのモデルも、放っておくと「年間500冊読む僕」「顧客との交渉が…」といった、**ありもしない経歴を勝手に創作して**、読者に説教を始める。これはサイズを上げても消えない。そこでプロンプトに「元メモにない事実を作らない」「読者に呼びかけない」「大仰な決め言葉を使わない」というガードを明示的に足した。すると、同じモデルでも出力が見違えて落ち着いた。

規律がプロンプト側で担保できたので、モデルは純粋に「日本語の流暢さ」で選べばよくなった。結論は **Gemma 4 の26B（`gemma4:26b`・約17GB）**。文章のなめらかさが頭ひとつ抜けている。24GBだとメモリはギリギリで、重いときは他のアプリを閉じるかGPU上限を上げる必要があるが、その価値はあった。

```python
# 既定モデル。環境変数や --model で差し替え可能
MODEL = os.environ.get("OLLAMA_MODEL", "gemma4:26b")
```

実行はOllama経由。`ollama pull gemma4:26b` で入る。別のモデルを試したくなっても `--model gpt-oss:20b` のように1行で切り替えられるようにしてある。

## Obsidianからスクリプトをどう起動するか

ここが地味に最大の関門だった。**Obsidianは、単体ではシェルやPythonを起動できない。** ボタンを押して外部スクリプトを走らせるには、橋渡しが要る。

使ったのは「Shell commands」というコミュニティプラグインだ。これを入れると、任意のシェルコマンドをObsidianのコマンドとして登録でき、それをボタンから呼べる。登録するのはこれだけ。

```bash
cd "/Users/okamiyatakashi/Developer/ObsidianVault" && /usr/bin/python3 draft_generator.py
```

ひとつハマったのを書いておく。最初、パスをプラグインの変数 `{{vault_path}}` で書いていたら、`zsh:cd:no such file or directory` で動かなかった。原因は、プラグインが変数の値を自動エスケープして `/` を `\/` に変換し、それをダブルクォートで囲っていたせいだった。**クォートの外なら `\/` は `/` に戻るが、クォートの中だと文字として残る。**

ボタン自体は、もともと入れていた「Buttons」プラグインで置いている。押すと先ほどのコマンドが走り、`Draft` に下書きが落ちてくる。

## 同じネタを何度も書かせない工夫

動かし始めてすぐ気づいた問題がある。**放っておくと、AIは似たネタばかり選んでくる。** 「読書法」が魅力的なタネだと、毎回それを選ぶ。これでは下書きが重複する。

そこで、生成するたびに**元ネタを履歴ファイル（`.draft_history.json`）に記録**するようにした。次回からは、この履歴と、`04_Draft` にまだ残っている下書きの両方を見て、**使用済みのネタを候補から外してから**AIに選ばせる。下書きを `publish` に移してフォルダから消えても、履歴は残るので忘れない。

```python
def used_source_titles() -> set[str]:
    """履歴 + Draftに残る下書きの両方から「使用済みネタ」を集める"""
    used = {h.get("source_title", "") for h in load_history()}
    for p in DRAFT_FOLDER.glob("*.md"):
        m = re.search(r'^source_note:\s*"?\[\[(.+?)\]\]"?', read_text(p), re.MULTILINE)
        if m:
            used.add(m.group(1))
    return used
```

あえて作り直したいときは `--force`、これまで何を書かせたか振り返りたいときは `--history` で見られるようにした。未生成のタネが尽きたら「ネタが尽きました」と教えてくれる。そうしたら新しい考えごとをメモする——つまり、**この仕組みが僕に「考えろ」と促してくる**わけだ。悪くない循環だと思う。

## 細かいハマりどころ

実運用に乗せる過程で踏んだ小さな穴も、いくつか塞いだ。

モデルを取っ替え引っ替えして気づいたが、推論型のモデルは答えの前に `<think>…</think>` という思考の独り言を出すことがある。そのまま下書きに混ざると邪魔なので、本文から正規表現で除去するようにした。今の既定（Gemma 4）では出ないが、モデルを差し替えても安全なように残してある。コードブロックで全体を囲って返してくる癖も同じく剥がす。

## 使ってみて

この仕組みを入れてから、メモを放り込む手が軽くなった。前は「これ、ちゃんと記事にできるかな」と無意識にブレーキを踏んでいた。でも今は、**雑なタネでも投げておけば、いつかAIが拾って下書きにしてくれる**と分かっている。だから気軽に散らかせる。

セカンドブレインは、ためるだけだと物置になる。少し前に[[溜まり続けるノートのタグ付けを、AIに毎晩やってもらうことにした]]で「整理」を手から外したが、今回はその先の「アウトプット」まで手から外した。考えをためる→勝手に整理される→勝手に下書きになる。この流れができてくると、Vaultが少しずつ、自分で回り始める感覚がある。

本当は、これを毎朝自動で走らせて、起きたら下書きが1本ある状態にしたい。`launchd` で深夜に1本生成しておけば、朝の自分はただ「直して公開する」だけでよくなる。書くという行為の、いちばん重い部分を、機械に肩代わりしてもらう。その実験はまだ続きそうだ。
